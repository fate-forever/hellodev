# HelloDev Core 0.21.3 release checklist

0.21.3 packages one project-discoverable HelloDev Agent Skill so Codex, Cursor and Antigravity can load the governed workflow and bounded recovery guidance without a long user prompt. It preserves 0.21.2 recoverable closure, Core-enforced acceptance and approval boundaries, exactly six MCP tools, the six-field default `open`, host-asserted trust labels and a non-executing Core.

## Required checks

1. Version `0.21.3` agrees in package metadata, `__version__`, component lock/schema, bundle metadata, Dashboard, README and tests.
2. A Trellis task set containing `README.md` or `.gitkeep` does not conflict between prepare and run.
3. `do begin` discloses a conservative closure plan, including host command, level and scope.
4. Windows npm launcher aliases share an evidence hash only for explicitly supported, metacharacter-free forms.
5. Repeated `--result-json` or PowerShell-safe `--result` records 1-16 current-snapshot results atomically and refreshes the WorkItem projection.
6. Trellis completion writes mergeable, hash-only `.gates/hellodev-quality.json` without overwriting a user gate.
7. Fresh/unbound `open` returns exactly one structured `begin-work` action and never recommends `do plan`.
8. Daily lifecycle and verification operations fail closed without the required WorkItem/AcceptanceContract identity.
9. `finishPolicy=suggest` never permits missing identity or unsatisfied acceptance.
10. Trellis `task-begin` is one-approval, recoverably idempotent and binds task, WorkItem and AcceptanceContract without native fallback.
11. Multiple Trellis tasks select only one uniquely aligned candidate; ambiguity returns bounded exact actions.
12. Manifest-first ordered verification, snapshot invalidation and unchanged-failure diagnostics remain intact.
13. Dashboard schema 23 exposes only sanitized binding/closure integrity and a compact next action.
14. A project-relative UTF-8 `--requirements-file` is copied exactly with a stable digest; unsafe, missing or changed sources fail closed.
15. A strict change spanning more than ten files cannot close from a summary-only contract.
16. WorkItem-backed low-level lifecycle completion is rejected; managed finish requires active Trellis state, task-complete receipt, mergeable quality evidence and a refreshed finished WorkItem.
17. Exact requirements project into bounded criteria and manifest-derived progressive gates without executing commands or creating verification evidence.
18. Every successful daily/acceptance response exposes one normalized `nextAction`; approval responses preserve the exact resume command.
19. Trellis preflight rejects unsafe/invalid manifests and never claims native validation or quality-gate success.
20. Only isolated project-context drift auto-refreshes; authority, workflow, configuration, component and tool drift still fail closed.
21. Daily operation timing is local monotonic, non-persistent and never represented as Agent time or token usage.
22. Finish before `checking` creates no approval, closure transaction, receipt, component operation or Trellis mutation.
23. A native-completed closure resumes without executing the Trellis adapter again; an unambiguous legacy partial commit can re-enter check and be adopted.
24. Trellis task/gate transitions preserve current host verification evidence while source changes still invalidate it.
25. Bare verify fails with a bounded `ProjectError`; confirmation, repair and diagnostic responses progressively disclose exact Agent guidance.
26. The wheel contains one valid `hellodev` Skill, its OpenAI UI metadata and one progressive recovery reference.
27. Cursor onboarding installs only `.cursor/skills/hellodev`; Codex and Antigravity install only `.agents/skills/hellodev`; `host=none` installs no Skill.
28. Skill conflicts and unsafe paths fail before project state, MCP config or host rules are mutated; unchanged managed installs are idempotent and user-modified installs are never overwritten.
29. Focused, compatibility, fast/full, compile and Dashboard syntax gates pass.
30. A clean isolated wheel reports the expected version, six MCP tools and six-field default `open`, and installs the project Skill without global writes.

## Publication boundary

Building `dist/hellodev_core-0.21.3-py3-none-any.whl` is local validation only. Git push, tag, GitHub Release, PyPI upload, release snapshot, bundle publication, global installation and user configuration changes require separate user authorization.
